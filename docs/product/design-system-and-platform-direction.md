## 업데이트 2026-11-11 (강사 앱 1.0.7 추가 변경 공유 반영)
출처: 강사 앱 쪽 공유문. 폰(DEV)에서 직접 확인한 것이 아니라 **공유문 기준**이다.

1. **방향 정리**: 이 문서의 목적은 "강사 앱을 기준으로 회원앱 작업지시서를 만드는 것"이다. 강사 앱은 기준이므로 바꾸지 않고, 강사 앱에서 발견한 문제는 아래 4장 표를 "강사 앱 개선 후보(참고)"로만 쓴다. 포인트 색은 **골드(브랜드 노랑)** 이며 앞서 검토한 주황 안은 폐기한다(브랜드 이미지: 남색 + 노랑/금색, 로고 노랑 `#F1CB25` / 앱 `#EFCB62`).
2. **글자색 대비 규칙(회원앱에 적용)**: 연한 골드(`#EFCB62`)를 흰 배경 위 **글자·아이콘·테두리선**으로 쓰면 대비가 약 1.5:1이라 거의 안 보인다. 글자·아이콘·선으로 쓸 때는 같은 색상(hue)을 어둡게 해서 대비 4.5:1 이상으로 맞춘다. **배경으로 칠하는 골드는 그대로** 쓴다. 다크 모드는 골드가 그대로 읽힌다. 레슨 블록 배경색 위 글자는 흰색/`#1F2937` 중 대비 큰 쪽으로 자동 전환(이전 공유 규칙)과 함께 쓴다.
3. **4장 항목 중 강사 앱에서 이미 처리된 것(공유문 기준, 폰 확인 전)**: 2번(라이트 "빠른 등록" 라벨: 키우고 아래로 내림), 3·4번(골드 글자 대비 규칙), 11번(하단 시스템 바 여백 보정: 설정·계약서 목록). 인사이트 하단 여백 등 나머지는 확인 필요.
   - **DEV 재확인 결과(2026-11-11, 라이트)**: "빠른 등록" 라벨은 진한 골드(`#8B7027`)로 바뀌어 흰 배경 위 대비 약 4.7:1로 **해결**. 설정 화면 맨 아래는 여백이 생겨 **해결**. 알림 설정의 꺼진 상태("선택됨", "진동만")는 개선됐지만(약 1.2:1 → 1.9:1) 4.5:1에는 못 미침 — 꺼짐(비활성) 표시라 감안해도 **부분 해결**. 회원 서명 요청 버튼 글씨·인사이트/계약서 하단은 이번에 다시 보지 못함.
4. **4장 1번(아나토미 저장 권한 오류)의 원인 후보**: 공유문에 따르면 없는 문서를 읽으면 Firestore가 "없음"이 아니라 `permission-denied`를 돌려준다. 이전 빌드에서는 레슨 전 체크리스트를 끝내야 `training_logs` 초안이 생겨, 체크리스트를 건너뛰면 "저장 권한이 없어 처리하지 못했습니다"가 보였을 가능성이 높다. 이제 아나토미 레슨일지를 열 때 초안(`status: "draft"`)을 먼저 만든다. **2026-11-11 DEV 1.0.7-dev 새 빌드에서 재확인: 아나토미 레슨일지가 정상으로 열림**(바디맵: 3D 마네킹, 선택 부위는 파란 하이라이트+주황 "!" 마커, 상단 3단계 표시 기록·영상 음성·확인 저장, "다음" 버튼은 골드).
5. **회원앱 영향(training_logs)**: 회원앱이 레슨일지를 보여 줄 때 `status == "draft"` 문서는 목록에서 제외한다. 현재 Rules상 `training_logs`는 강사 본인만 읽을 수 있어 회원앱 직접 조회는 막혀 있고, 서버 API 설계 시 이 점을 반영한다. 회원앱이 보여 줄 범위(아나토미 요약 `anatomyRecordCount` 등)는 **사장님 결정 대기**. 문서 존재 확인도 `permission-denied` 동작을 가정한다.
6. 변하지 않은 것: 레슨 종류 목록(이름+색)은 강사 폰 로컬에만 있어 회원앱은 `schedules` 문서의 `typeColorHex`(`#RRGGBB` 대문자)만 쓸 수 있다. 사인 출석 서버 API는 1.0.7 출시 후 로그인 방식 확정부터. 서버(Rules·Functions·인덱스)와 데이터 구조는 이번에도 변경 없음.

- 강사 앱: **MORE THAN**
- 회원앱: **MORE THAN wellness** (화면에서는 "MORE THAN" 대문자 + "wellness" 굵은 소문자)

## 3. 색과 테마

### 3.1 현재 상태 (확인한 것)
| | 강사 앱 | 회원앱 |
|---|---|---|
| 바탕 | 라이트: 아이보리(`#F7F5EF`) + 네이비 헤더 / 다크: 네이비(`#071522`~`#0B1E32`) | 다크 네이비 + 우상단 갈색 그라데이션 |
| 포인트 | 골드 `warmYellow #EFCB62` | 주황(화면 추정 `#EF8250` 근처, 코드 값은 확인 필요) |
| 카드 | 둥근 카드, 얇은 테두리 | 더 큰 반경, 단색 채움 카드 |
| 하단 | 흰/네이비 바 + 가운데 골드 "빠른 등록" 원형 버튼 | 떠 있는 알약형 바, 선택 탭 알약 강조 |
| 제목 | 한글 굵은체 | 영문 대문자 라벨 + 한글 굵은 제목 |
| 테마 선택 | 설정에 3종: 라이트("MORE THAN 네이비와 웜 옐로우"), 다크, **룰루랄라**(인디고·퍼플, 예전 테마) | 확인 필요 |

공통 기반은 **네이비 계열 바탕, 카드 면+얇은 테두리, 굵은 한글 제목**이다. 이 기반은 유지한다.

### 3.2 결정 방향
1. **브랜드 포인트 색은 주황 하나**로 한다. (사장님 확정 필요, 아래 8장)
   - 라이트/다크에서 **같은 색상(hue)** 을 쓰고 명도만 조정한다. 다크는 밝은 주황, 라이트는 조금 더 진한 주황.
   - 이유: 골드는 라이트 배경에서 대비가 약하다(라이트 홈의 "빠른 등록" 글씨가 흰 배경에서 거의 안 보임). 주황 바탕에는 네이비/검정 글씨를 쓴다.
   - 시안 비교(주황 기준/골드 기준 나란히)를 만들어 보고 확정해도 된다.
2. **골드는 보조색**으로 남긴다: Pro 배지, 회원 등급, 후원 같은 "특별 표시".
3. **레슨 종류 색은 브랜드 색과 분리**한다.
   - 1.0.7부터 강사가 레슨 종류의 이름과 색을 직접 정하고(고정 10색 + 직접 고르기), 계약서 바인더 색·홈 시간표·위젯이 같은 색을 쓴다. 글자색은 배경 대비에 따라 흰색/`#1F2937` 자동 전환.
   - 따라서 브랜드 주황은 **버튼·선택 상태·강조**에만 쓰고, 레슨 블록 색에는 쓰지 않는다. 기존 `lessonGroup`(주황 `EA580C`)처럼 브랜드 주황과 겹치는 레슨 기본색은 정리 대상이다.
   - PT의 기본 색은 인디고. 브랜드 색으로 바뀌어도 바인더·블록은 레슨 색을 따른다.
4. **다크/라이트 규칙**: 공통은 포인트 색, 반경, 버튼 모양, 글꼴, 상태 색. 모드별로 다른 것은 배경·카드 면·테두리·글자색. 두 앱 모두 시스템 설정을 따르고 사용자가 바꿀 수 있다. 기본값은 강사 앱 라이트 우선, 회원앱 다크 우선.
5. **룰루랄라 테마**는 폐기 여부를 결정해야 한다 (현재 사용자가 선택 가능). 폐기하면 `lululala*` 색 상수와 인디고·퍼플 사용처를 정리한다.

### 3.3 공통 규칙 초안 (값은 구현 단계에서 확정)
- 카드 반경: 회원앱 기준(큰 반경)을 따른다. 강사 앱은 점진 정렬.
- 버튼: 주 버튼=포인트 색 바탕+어두운 글씨, 보조=테두리, 위험=상태 색.
- 제목: "영문 대문자 라벨 + 한글 굵은 제목"은 회원앱 고유 톤으로 유지, 강사 앱은 선택 적용.
- 빈 상태: 항상 다음 행동 문구를 둔다 ("첫 식사를 기록해 보세요" 식).
- 반드시 대비 확인: 주황 위 글씨, 라이트에서의 보조 글씨.

## 5. 홈 타일 구조와 가운데 바로가기 시트

### 5.1 홈 타일 (두 앱 공통 개념)
- 큰 카드 세로 나열 대신 **2열 타일**. 크기는 전체 폭/반 폭 두 종류.
- 각 타일은 **데이터 있음 / 없음** 두 상태를 가지며, 없음일 때 다음 행동 문구를 보여 준다.
- 타일 면은 카드 색으로 통일하고 포인트 색은 아이콘·숫자에만. 삼성헬스처럼 타일마다 다른 색을 쓰지 않는다(통일 원칙과 충돌).
- 단계: (1) 구조 변경 (2) 상황별 자동 우선순위 (예: 사인 요청이 있으면 사인 타일이 맨 위, 코치 미연결이면 코치 연결 타일 맨 위) (3) 사용자 편집(순서·숨김). 3단계는 저장 위치(기기/서버) 결정과 새 의존성 가능성 때문에 별도 승인.
- 회원앱 홈 기본 타일 후보: 코치 연결, 운동 시작, 칼로리·식단, 운동 시간, 사인 출석.
- 강사 앱 홈 타일 후보: 오늘 다음 레슨, 이번 주 스케줄, 후원 배너(숨김 가능).

### 5.2 가운데 바로가기 시트 (강사 앱)
- 하단 바 가운데에 **고정**(떠다니지 않음). 지금 가운데는 "빠른 등록" 골드 버튼이며, 스케줄 칸을 가리는 문제가 있었다.
- 탭하면 아래에서 시트가 올라와 3~5개 바로가기를 보여 준다. **"빠른 등록"은 첫 칸 고정**, 나머지는 사용자가 고른 자주 찾기.
- 추천("이렇게 사용해 보세요")은 **별도 줄에 1~2개**만. 자주 찾기 칸 순서를 자동으로 바꾸지 않는다.
- 키보드가 올라오는 화면, 사인창, 레슨 편집 화면에서는 숨긴다. 계속 움직이는 애니메이션은 쓰지 않는다.
- 사용 횟수는 **기기 안에만** 저장(서버 전송은 개인정보 정책 변경이므로 별도 승인). 추천은 한 번에 하나, "그만 보기" 제공, 이미 쓴 기능은 제외, 레슨/입력 중에는 띄우지 않음.
- 홈 타일 편집과 같은 "즐겨찾기" 설정을 공유할 수 있다.
- 회원앱은 하단 탭 4개(홈·운동·커뮤니티·마이)를 유지하고 가운데 버튼은 두지 않는다.

## 6. 사인창·채팅창·커뮤니티

### 6.1 사인창 (회원앱 사인 출석)
- 서버 API 선행: `inspectMemberAttendanceV1`/`submitMemberAttendanceV1` 등은 아직 없음. 지금은 화면 구성만 정의.
- 서명 영역은 **라이트/다크와 무관하게 밝은 종이색 배경+진한 잉크색 고정**. 어떤 테마에서도 서명이 같게 보이고 계약서 삽입에도 유리.
- 위: 레슨 요약(코치 공개 활동명, 레슨명, 시간). 아래: "내용 확인" 체크, 지우기, 제출.
- 제출 후 상태 문구는 제안서대로 "사인 제출됨 · 강사 확인 대기". 서버가 `confirmed`를 줄 때만 완료 표시.
- 키보드·떠 있는 버튼 숨김.

### 6.2 채팅창 (후속)
- 내 말풍선: 포인트 주황 + 어두운 글씨. 상대: 카드 면 색.
- 사인 출석 요청·계약서 서명 요청은 대화 중간 **카드**로 끼우고 "사인하기" 버튼으로 이어진다.
- 서버 구조가 없으므로 구현은 사인 출석 API 이후.

### 6.3 커뮤니티
- 자유 대화. 후기·별점 기능은 만들지 않는다.
- **@멘션(태그) 기능 없음**: 특정 계정에 글이 연결되지 않아 트레이너 프로필·알림·추천과 기술적으로 분리된다.
- 글 안에 이름을 쓰는 것은 막지 않는다. 자정작용에 맡기고, 직접 비방·욕설만 제재한다.
- 운영 규칙: 신고 → 글 숨김 → 경고 → 이용 정지. 욕설은 자동 필터로 먼저 거른다. 신고가 일정 수 이상이면 글 자동 숨김(1인 운영 부담 완화). 작성 시 짧은 안내("특정인을 거론하는 내용은 신고될 수 있어요").
- 금지: 연락처, 가격 홍보, 외부 링크. 트레이너 계정은 커뮤니티 **글쓰기 불가**(광고판 방지). 트레이너는 자기 프로필 노출로만 광고하며 "광고" 표시를 단다. 자기 관련 신고에 대한 이의 제기 경로를 둔다.
- 가입 연령: **만 14세 이상**(확정). 만 14세 미만(키즈)은 법정대리인 동의 방식과 함께 키즈 레슨 기능을 열 때 다시 설계.
- 인증(식단·운동): 1단계는 글+체크형 기록(오늘 식단 3끼 완료, 운동 40분 등). 사진은 2단계(압축·크기 제한·보관 기간·삭제 요청 처리, 요금제 변경 가능성 → 승인 필요). 현재 회원앱은 인증 이미지 업로드가 무료 범위에서 꺼져 있다.

## 7. 관심사 태그와 매칭 신뢰 지표

### 7.1 관심사 태그 (회원 설정)
- **대분류 → 세부** 2단계. 예: 재활 → 손목·어깨·허리·기타(직접 입력) / 필라테스 → 자이로토닉·바렐·매트·기타(직접 입력).
- 대분류 복수 선택, 세부 복수 선택(최대 개수는 8장 결정 대기, 가정: 세부 최대 3개), 언제든 수정 가능.
- **세부 선택은 건너뛸 수 있다**: 대분류만 고르면 "재활(전체)"로 저장, 옆에 "세부 선택(선택)"을 작게 안내.
- "기타" 직접 입력은 표준 목록에 바로 반영하지 않는다. 같은 입력이 여러 번 나오면 사장님이 확인해 표준 목록에 올린다. 직접 입력은 실적 집계에 넣지 않는다.
- 회원 관심사와 트레이너 전문 태그는 **같은 표준 목록**을 쓴다. 강사 앱에 `personal_member_taxonomy_management_page.dart`가 있으나 연결 가능 여부는 코드 확인 필요(기본 레슨 종류 6종 PT·필라테스·요가·그룹·줌바·재활과도 이름이 겹침).
- 건강 관련 태그(재활, 통증)는 **민감정보**로 일반 마케팅 동의와 **별도 동의**를 받고 철회할 수 있어야 한다.

### 7.2 실적 기반 전문성 (후기·별점 대체)
- 표시 예: "같은 목적의 회원 10명을 지도 중". 트레이너가 해당 태그 회원을 많이 지도하면 전문성이 숫자로 드러난다.
- 집계 대상: **회원 본인이 설정한 관심사** 기준, 그리고 **회원이 직접 사인한 출석 기록이 일정 횟수 이상**인 연결 회원만. 가짜 회원으로 숫자를 올리는 것을 막는다. (사인 출석이 신뢰 체계의 뼈대)
- 개인을 알아볼 수 없게 합산하고, 일정 인원(가정: 5명) 이상일 때만 "10명+"처럼 구간으로 보여 준다.
- 표현은 사실 서술("손목 관련 회원 10명 지도 중"). "재활 전문가 인증" 같은 표현은 의료 오인 소지가 있어 쓰지 않는다.
- 후기·별점·체크형 평가는 만들지 않는다.

### 7.3 추천
- 회원 관심사 태그 ↔ 트레이너 전문 태그·실적으로 **규칙 기반** 매칭. 지역·인기 트레이너(관리 회원 수)도 같은 틀. AI는 "왜 추천하는지" 설명용으로 나중.
- 마케팅·추천 동의를 먼저 받는다.
