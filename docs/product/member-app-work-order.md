# MORE THAN wellness (회원앱) 디자인 통일 작업지시서 (초안)

작성: 2026-11-11. 기준 문서: `design-system-and-platform-direction.md`, `member-app-integration-notes.md`.
상태: **2026-11-11 사장님 결정 5건 반영(7장).** 회원앱 코드는 이 저장소에 없다. 그래서 값은 강사 앱(`lib/theme/app_colors.dart`)과 폰 화면에서 읽은 것이고, 회원앱 쪽 현재 값은 화면에서 추정한 것이다. 각 항목에 "확인" 표시를 두었다.
범위: **회원앱의 화면 디자인만.** 서버(Rules·Functions·컬렉션), 로그인·개인정보 정책, 결제는 이 문서 범위 밖이며 해당하는 항목은 "별도 승인"으로 표시했다.

## 0. 원칙
1. **강사 앱이 기준이다.** 강사 앱은 바꾸지 않는다. 회원앱이 강사 앱의 색·모양·규칙을 따른다.
2. 브랜드 정체성은 **남색 + 골드(노랑)**. 포인트 색은 골드 하나이며, 현재 회원앱의 주황은 폐기한다.
3. 두 앱이 같은 회사 앱으로 보이되, 회원앱 고유의 톤(영문 대문자 라벨 + 굵은 한글 제목, 다크 우선)은 유지할 수 있다.
4. 앱 이름: 회원앱 표시 이름은 **MORE THAN wellness**. 패키지 ID(`com.morethanwellness.app`)는 바꾸지 않는다.

- 브랜드 로고용 노랑은 `#F1CB25`(더 선명). **앱 안 포인트 색에는 쓰지 않고** 로고·스플래시·홍보 이미지에만 쓴다.

### 1.2 골드 사용 규칙 (글자색 대비)
- 연한 골드(`#EFCB62`)를 **배경으로 칠하는** 곳(버튼, 선택 칩, 원형 아이콘 배경, 오늘 강조 등)은 그대로 쓴다.
- 연한 골드를 **글자·아이콘·테두리선**으로 쓸 때, 흰/아이보리 배경 위에서는 같은 색상을 어둡게 해서 대비 **4.5:1 이상**으로 맞춘다. 회원앱 기준값은 **`#856A22`** (흰 `#FFFFFF` 위 5.1:1, 아이보리 `#F7F5EF` 위 4.7:1 실측). 강사 앱이 쓰는 `#8B7027`은 흰 위 4.7:1이지만 아이보리 위에서는 4.3:1로 기준 미달이라 회원앱은 쓰지 않는다.
- 다크 모드에서는 연한 골드를 글자·아이콘에 그대로 써도 된다(남색 위 약 9~10:1).
- 비활성(꺼짐) 상태라도 글자는 가능하면 3:1 이상. 강사 앱 알림 설정의 꺼짐 표시는 약 1.9:1로 약해서 **따라 하지 않는다.**

### 1.3 상태 색
성공 `#10B981`(글자 라이트 **`#047857`** — 강사 앱의 `#059669`는 흰 위 3.8:1이라 쓰지 않음, 다크 `#34D399`), 진행 `#3B82F6`(글자 라이트 `#2563EB`, 다크 `#60A5FA`), 오류/노쇼 `#EF4444`(글자 라이트 `#DC2626`, 다크 `#F87171`), 대기 `#D1D5DB`(글자 라이트 `#6B7280`). 점+글자 방식(배경 없음)을 쓴다.

### 1.4 레슨 색 (강사가 정한 색을 그대로 표시)
- 회원앱이 레슨 블록을 보여 줄 때 배경색은 `schedules` 문서의 `typeColorHex`(`#RRGGBB` 대문자)만 쓴다. 레슨 종류 목록 전체(이름+색)는 강사 폰 로컬에만 있어 읽을 방법이 없다(서버 동기화는 미정).
- **글자색 자동 전환**: 배경 상대 휘도를 구해 흰색(`#FFFFFF`)과 `#1F2937` 중 **대비가 큰 쪽**을 쓴다. 아주 밝은 배경(흰색 등)에는 옅은 회색 테두리를 더한다.
- 브랜드 포인트(골드)는 레슨 블록 색으로 쓰지 않는다. 레슨 색은 강사가 정한 색이고, 골드는 UI 강조용이다.

**한 화면에서 쓰는 방식(예)**: 바탕 `bg` → 카드 `surface`+`border` → 카드 안 입력 `surface2` → 제목 `text`, 설명 `textSub` → 강조 숫자·아이콘 `accentText` → 주 버튼 `accent`+`onAccent`. 다크는 "남색 면 위의 골드", 라이트는 "아이보리 위의 흰 카드, 골드는 채움 버튼과 진한 골드 글자".

**바디맵 색(결정 3 반영)**: 선택 부위 채움 `accent` 70%(다크·라이트 공통), 선택 테두리 `accentText`, 선택 안 된 부위는 `surface2`와 `border`. 주황 마커·파란 하이라이트는 쓰지 않는다. 이전 기록이 있는 부위의 표시는 `accentText` 점.

**검증 요청**: 작업자는 구현 후 두 테마의 홈·운동·마이 3화면을 캡처해 이 표의 대비 수치가 지켜졌는지 확인한다. `surface2` 라이트 값은 새로 정한 것이라 카드 위에서 구분되는지 눈으로도 확인한다.

## 2. 공통 컴포넌트 지시
구체 px(반경, 패딩)은 강사 앱 코드의 값을 따른다(작업자가 확인). 아래는 모양 규칙이다.

| 컴포넌트 | 규칙 |
|---|---|
| 카드 | 라이트: 흰 면+아주 연한 그림자+얇은 테두리. 다크: 카드 면 색+얇은 테두리. **평평하게.** 금속 광택·파스텔 그라데이션 금지 |
| 기본 버튼 | 골드 바탕 + 남색 글씨(굵게). 화면당 1개 |
| 보조 버튼 | 테두리만(라이트: 흰 면+연한 테두리), 글씨는 남색/기본 글자색 |
| 선택 칩 | 라이트: 남색 채움+흰 글씨. 다크: 골드 또는 카드 2단계 색. 선택되지 않은 칩은 테두리 |
| 입력 | 면은 카드 색보다 한 단계 어둡거나 밝은 회색, 포커스는 골드 테두리 |
| 아이콘 버블 | 라이트: 연한 골드 바탕+남색 아이콘. 다크: 어두운 골드 틴트(`#1F1600` 계열)+골드 아이콘 |
| 헤더 | 남색, 아래가 둥글게 휘고 얇은 골드 빛 테두리. 화면마다 모양을 **하나로 통일**(전체 곡선) |
| 하단 바 | 라이트: 흰 바, 다크: 남색 면. 선택 탭은 골드 강조. **시스템 내비게이션 바 위쪽으로 안전 여백 확보**(글자가 내비게이션 아이콘 밑에 겹치지 않게) |
| 시트/다이얼로그 | 라이트: 흰 시트+남색 머리, 버튼은 골드. 다크: 카드 색. **보라/인디고 머리 금지** |
| 토스트 | 남색 면+흰 글씨 |
| 빈 상태 | 짧은 안내 + **다음 행동 버튼 한 개**. 화면 중앙 배치, 오류 카드가 위쪽에 붙지 않게 |
| 오류 상태 | 한 문장 + 다시 시도. 중앙 배치, 제목 영역 유지 |

금지(회원앱에 가져오지 않는 것): 헤더 아래 보라 빛, 금속 광택 카드, 인사이트식 파스텔 그라데이션 카드, 갈색 후원 배너 스타일, 로열 블루 선택 테두리, 인디고·보라 포인트(레슨 색으로 강사가 고른 경우 제외), 개발자용 안내 문구.

## 3. 화면별 지시 (회원앱 현재 화면 기준)

### 3.1 홈
- 큰 카드 세로 나열을 **2열 타일**로. 타일 크기는 전체 폭/반 폭 두 종류.
- 타일은 **데이터 있음/없음** 두 상태. 없음일 때 다음 행동 문구(예: "첫 식사를 기록해 보세요").
- 타일 면은 카드 색으로 통일하고, 포인트 색은 아이콘·숫자에만. 타일마다 다른 색 금지.
- 기본 타일 후보: 코치 연결, 운동 시작, 칼로리·식단, 운동 시간, 사인 출석.
- **자동 우선순위(2단계)**: 사인 요청이 있으면 사인 출석 타일이 맨 위, 코치 미연결이면 코치 연결 타일이 맨 위.
- **사용자 편집(결정 4: 진행)**: 편집 모드에서 타일 순서 변경·숨김. 설정은 1차로 **기기 로컬 저장**(서버 저장은 계정 간 동기화가 필요해질 때 별도 승인). 드래그 정렬용 새 패키지가 필요하면 **추가 전에 멈추고 승인**(기본 Flutter `ReorderableListView/GridView`로 먼저 시도).
- **자주 쓰는 것 추천(AI 기능처럼)**: 1단계는 **규칙 기반**. 타일·바로가기별 진입 횟수를 기기에 세고, 최근 14일 사용 빈도가 높은 순으로 위로 올릴 후보를 제안한다("자주 여는 '식단'을 위로 올릴까요?" → 수락/나중에). 사용자가 직접 정한 순서가 항상 우선이며, 자동으로 몰래 재배치하지 않는다. 같은 규칙으로 안 써 본 기능 안내("이렇게 사용해 보세요")를 하루 1개 이하로 노출. 서버 AI는 설명 문구 용도로 후속 검토.
- 우선순위 합산 순서: ① 사인 요청 ② 코치 미연결 ③ 사용자가 고정한 순서 ④ 빈도 추천.
- 가로 스크롤 카드가 옆 카드를 잘라 보이게 하지 말 것(스크롤 가능 표시를 주거나 2열 고정).
- 현재 우상단 갈색 그라데이션은 남색 그라데이션 헤더로 교체.

### 3.2 운동
- 영문 라벨 "MOVE LIBRARY" + 굵은 제목 구조는 유지(회원앱 고유 톤).
- "개인 운동일지 열기"는 보조 버튼, 검색 입력은 1.1/2장 입력 규칙.
- 신체 이미지(남녀 앞면/뒷면)의 **파란 사각 배경을 제거**하고 카드 색 안에 배치(투명 배경 또는 카드 면 색).
- 선택 부위 표시는 **골드 계열**(결정 3). 색은 1.5절 "바디맵 색"을 따른다. 강사 앱 바디맵(파란 하이라이트+주황 마커)은 참고하지 않는다.
- 앞면/뒷면 전환은 선택 칩 규칙.

### 3.3 커뮤니티
- 오류 화면: 제목 영역 + 중앙 배치 + 다시 시도(골드 버튼).
- 정책(별도 승인): **@멘션 기능 없음**, 후기·별점 없음, 트레이너 계정은 글쓰기 불가, 신고→숨김→경고→정지, 연락처·가격 홍보·외부 링크 금지, 신고 일정 수 이상이면 글 자동 숨김, 작성 시 짧은 안내("특정인을 거론하는 내용은 신고될 수 있어요"). 가입 연령 만 14세 이상.
- **게시 공개 범위(결정 5, 초안 — 확정 전 별도 승인)**: 글쓰기 화면에 공개 범위 선택을 둔다. 기본값은 가장 좁은 것.
  | 범위 | 누가 보나 | 필요한 데이터 | 단계 |
  |---|---|---|---|
  | 나만 보기 | 본인(기록 보관용) | 없음 | 1 |
  | 소속 트레이너 게시판 | 같은 트레이너에 연결된 회원(트레이너는 읽기만) | 회원–트레이너 연결 | 2 (정정 2026-11-11: 개인 전송이 아니라 게시판) |
  | 전체 공개 | 모든 가입 회원 | 없음 | 1 |
  | 소속 헬스장 게시판 | 같은 헬스장 소속 회원(트레이너는 읽기만) | 회원앱에 헬스장 소속 정보 필요 | 2 |
  | 같은 지역 | 같은 시·구 회원 | 지역 정보(위치정보 동의 검토) | 2 |
  - "트레이너 공개"는 **모든 트레이너가 아니라 연결된 내 코치**로 한정한다(트레이너는 글을 쓰지 못하고 읽기만).
  - 헬스장·지역은 회원이 직접 고르는 값만 쓰고 GPS 자동 수집은 하지 않는다. 지역은 시·구 단위까지만 표시.
  - 만 14~17세 회원은 기본 "나만 보기"이고 전체 공개 시 안내를 한 번 더 보여 준다(법적 확인 필요).
  - 이미 올린 글의 범위는 나중에 좁힐 수 있다(넓히기는 확인 한 번).
  - 범위가 좁을수록 신고·운영 부담이 줄고, 넓을수록 커뮤니티 활성도가 올라간다. 초기 회원 수가 적을 때 같은 헬스장·같은 지역은 볼 글이 없어 **텅 빈 화면**이 되므로 2단계로 둔 것이다.
- 1단계 인증은 글+체크형 기록(오늘 식단 3끼 완료, 운동 40분 등). 사진은 2단계이며 요금제·보관 정책 결정 후(별도 승인).

### 3.4 마이
- **개발자용 안내문 제거**("추가 결제 없이 Firebase 무료 범위로 운영 중이에요…"). 출시 전 필수.
- 프로필 카드: 제목과 안쪽 카드 사이의 큰 빈 공간 제거, 카드 안 카드 금지.
- "ACTIVE PROFILE" 카드는 평평한 카드 규칙(큰 원형 장식 제거 여부는 사장님 선택).
- 이메일 같은 개인 정보 표시는 내 계정 화면에서만.

### 3.5 사인 출석 (서버 API 선행, 화면 구성만)
- 서명 영역은 **라이트/다크와 무관하게 밝은 종이색 바탕 + 진한 잉크색**으로 고정.
- 위: 레슨 요약(코치 공개 활동명, 레슨명, 시간). 아래: "내용 확인" 체크, 지우기, 제출(골드).
- 제출 후 문구 "사인 제출됨 · 강사 확인 대기". 서버가 `confirmed`를 줄 때만 완료 표시.
- 키보드가 올라오는 화면, 사인창에서는 떠 있는 버튼 숨김.
- 서버 API(`inspectMemberAttendanceV1`, `submitMemberAttendanceV1` 등)는 1.0.7 출시 후, 로그인 방식 확정부터. **지금은 구현하지 않는다.**

### 3.6 채팅 (후속)
- 내 말풍선: 골드 바탕+남색 글씨. 상대: 카드 면 색.
- 사인 출석·계약서 서명 요청은 대화 중간 카드 + "사인하기" 버튼.

### 3.7 관심사 태그 (자유 가입·매칭 대비, 별도 승인)
- 대분류 → 세부 2단계, 복수 선택, 언제든 수정. 세부 선택은 건너뛸 수 있고 "세부 선택(선택)"을 작게 안내. 대분류만 고르면 "재활(전체)"로 저장.
- "기타" 직접 입력은 표준 목록에 바로 넣지 않고 사장님이 검토. 직접 입력은 실적 집계에 포함하지 않는다.
- 재활·통증 같은 건강 관련 태그는 일반 마케팅 동의와 **별도 동의**, 철회 가능(법적 확인 필요).
- **1단계 선택 개수: 전체 합계 최대 5개**(폭을 넓게, 2026-11-11 확정). 선택 시점은 가입 직후 온보딩(건너뛰기 가능) + 마이에서 수정. 개수는 운영하며 조정 가능.

## 5. 서버·데이터 경계
- 서버(Rules·Functions·인덱스)와 데이터 구조는 **변경 없음**. 이 작업지시서로 규칙/함수/컬렉션 배포를 하지 않는다.
- 레슨 색: `schedules` 문서 `typeColorHex`(`#RRGGBB` 대문자)만 사용. 종류 목록 동기화는 미정(필요 시 팀원이 형태를 제안).
- `training_logs`: 현재 Rules상 강사 본인만 읽을 수 있어 회원앱 직접 조회는 막혀 있다. 회원앱이 레슨일지를 보여 줄 때는 `status == "draft"` 문서를 제외하고, 노출 범위(아나토미 요약 `anatomyRecordCount` 등)는 **사장님 결정 대기**. 문서 존재 확인은 `permission-denied`를 "없음"으로 가정.
- 새 의존성 추가는 승인 전 금지(예: 홈 타일 드래그 라이브러리).

## 6. 수용 기준 (작업 완료 체크)
- [ ] 회원앱 전체에서 주황이 포인트 색으로 남아 있지 않다 (상태 색 제외).
- [ ] 라이트/다크 모두에서 글자·아이콘·선으로 쓴 골드의 대비가 4.5:1 이상이다 (다크의 연한 골드는 예외).
- [ ] 레슨 블록 글자가 배경색 대비에 따라 흰색/`#1F2937`로 바뀐다. 흰색 배경 블록에는 테두리가 있다.
- [ ] 보라 빛, 금속 광택, 파스텔 그라데이션, 로열 블루 테두리가 없다.
- [ ] 헤더 모양이 모든 화면에서 같다.
- [ ] 하단 바/시스템 내비게이션과 글자가 겹치지 않는다.
- [ ] 개발자용 안내문이 없다.
- [ ] 빈 상태와 오류 상태가 중앙 배치되고 다음 행동이 있다.
- [ ] 홈 타일에 빈 상태 문구가 있다.
- [ ] 사인창은 테마와 무관하게 종이색 바탕이다.
- [ ] 코드/Firestore 규칙/함수 변경 없이 화면만 바뀌었다 (해당하면).
