# 레슨일지·훈련 캘린더 기획 인수인계 (2026-10-11)

새 세션에서 레슨일지/훈련 캘린더 기획을 이어가기 위한 문서다. 코드로 확인한 현황과 사용자가 정한 방향, 홈 채팅에서 나온 아이디어를 구분해서 적는다. 아이디어는 아직 결정이 아니다.

## 1. 현재 앱 현황 (코드 확인)

레슨일지 작성 방식 선택 시트(`lib/pages/personal_training_log_page.dart` `_openDraftEntryPicker`)에서 4가지를 고른다.

| 방식 | 파일 | 현황 |
|---|---|---|
| 텍스트 | `personal_training_log_text_voice_page.dart` | 자유 입력 + 음성 초안(원문 별도 보관, 저장 시 핵심 요약) |
| 카테고리 | `personal_training_log_category_page.dart` | 부위/운동 선택, 운동별 세트·반복·보조 횟수·메모. 레슨 전(컨디션·식사·수면·통증·스트레칭)/중(목표·집중 부위·반응)/후(통증 변화·수행도·다음 행동·숙제), 회원 공개용 요약·좋았던 점·숙제 안내·주의사항, 내부 메모 분리 |
| PDF | `personal_training_log_pdf_page.dart` | 77줄 자리표시 화면. "회원 공유용 PDF와 강사용 보관 PDF를 만들 수 있도록 확장할 예정" 문구뿐 |
| 아나토미 | `personal_training_log_anatomy/` | 바디맵 4단계(부위 → 운동 기록 → 영상·메모 → 확인). PRO 등급 전용(`canUseAnatomy`). 수치 필드 없음 |

별도로 빠른 레슨일지(`personal_training_log_quick_sign_page.dart`)가 있다: 메모 + 강사·회원 서명, 처리 4종(정상 차감 / 서비스 / 노쇼 차감 / 노쇼 미차감).

확인된 한계
- 펜(손글씨) 입력은 서명 화면 외에 없다.
- 어떤 방식에도 중량(kg) 필드가 없다. 세트·반복만 있고, 종목 단위 추세 누적 구조가 없다.
- 수업일지 서버 동의 강제 없음(클라이언트 guard만).

## 2. 사용자가 정한 방향

- 사용자는 태블릿 펜 수기로 레슨일지를 쓰는 것을 선호한다. 생각·느낀 점을 쓰기 편해서다.
- PDF 방식 = 사용자가 쓰던 일지를 스캔해서 그 위에 펜으로 작성하는 형식으로 만든다.
- 아나토미 방식 = 수기 작성 + 쉽게 체크체크로 넘어가는 방식을 함께 넣는다.
- 훈련 캘린더를 만들고 싶다. 동기: 회원이 많아질수록 회원별 훈련 방향·진행 상황을 기억하기 어렵다.

## 3. 홈 채팅에서 나온 아이디어 (미결정)

구조: PLAN(목표·집중 영역·프로그램 기간·주간 계획) → TRACK(수업일지의 종목·중량·횟수·세트로 계획 대비 실제 비교) → DECIDE(다음 훈련 검토 제안, 최종 판단은 강사).

우선순위로 제안된 것: 점진적 과부하 검토 제안, 근육군별 주간 세트, 목표별 처방 템플릿, 유연한 트레이닝 캘린더, 트레이너 대시보드(회원 목록에서 현재 집중 영역·진행 상태 요약).
주의로 제안된 것: RIR 필수 입력 금지(선택 기록), 모든 회원 주 10세트 고정 목표 금지, 추정 1RM 정체 알림을 확정 표현으로 쓰지 않기, 자동 증량 지시 금지.
수업일지 구조: 운동 기록(지난 수업 불러와 수정) / 수기 메모(관찰·판단) / 다음 수업 계획(수기에서 선택해 가져오기).
인바디 추이를 데이터로 연결하되 인바디만으로 판단하지 않는다.
개발 순서 제안: 집중 영역 설정 → 캘린더·기간 → 일지와 기록 연결 → 근육군별 훈련량 → 다음 훈련 검토 알림 → 회원별 현황 대시보드.
첫 결정 과제: 회원의 '현재 집중 영역'을 어떻게 정의할 것인가(트레이너가 직접 지정하는 방식에서 시작).

## 4. 열린 질문

- PDF: 스캔 이미지를 어떻게 가져올지(카메라 / 갤러리 / 파일), 결과를 이미지·PDF 중 무엇으로 저장할지, 회원 공유용과 강사 보관용을 나눌지.
- 펜 입력: 새 의존성 없이 `CustomPaint`(서명 화면 방식)로 충분한지, 필압·지우개·페이지·되돌리기 범위.
- 아나토미 체크 항목: 부위별로 무엇을 체크할지(통증, 가동범위, 수행 상태 등).
- 수치 데이터(종목·중량·횟수)를 수기와 별개로 어디에 가볍게 입력할지. 기존 카테고리 방식에 추가할지 새로 만들지.
- 사용 태블릿 기종과 S Pen 여부.
- 기존 Firestore 필드 호환성(AGENTS.md: 과거 데이터 호환 유지, 새 의존성 사전 승인).
