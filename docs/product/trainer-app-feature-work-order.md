# 강사 앱(MORE THAN) 기능 변경·추가 작업지시서 — 회원앱 연동·커뮤니티 그룹

작성: 2026-11-11. 상태: **초안, 사장님 검토 전.** 디자인 통일(`member-app-work-order.md`)과 별개의 **기능 작업**이다. 강사 앱 디자인은 이 문서에서 바꾸지 않는다.
관련: `member-app-feature-direction.md`(그룹 모델·공유 구조), `member-app-integration-proposal-2026-11-05.md`(연결·사인 API 제안), `legal-check-bundle.md`.
**AGENTS.md 적용**: Firebase Rules·Functions 배포, 새 컬렉션/필드, 인증, 개인정보 정책, 새 의존성, 회원 데이터 구조 변경은 구현 전에 멈추고 승인받는다. 이 문서의 각 단계는 **승인 게이트**를 명시한다. 한 번에 한 단계만 작업하고 다음 단계로 자동 이동하지 않는다.

## 0. 목적
1. 강사가 **커뮤니티 그룹**을 만들고, 회원을 **초대 링크**로 회원앱에 연결하며, 초대할 때 어느 그룹에 넣을지 고른다.
2. 연결된 회원에게 레슨 알림·일정 공유·레슨 사인·채팅이 열릴 기반을 만든다(채팅·사인은 후속).
3. 강사는 자기 그룹 게시판을 **읽기만** 한다(글쓰기 없음).

## 1. 현재 코드 상태 (확인한 사실)
| 항목 | 상태 |
|---|---|
| 회원 분류 그룹 | `trainer_profiles/{uid}/personal_groups`, 회원 문서의 `personalGroupId`(회원당 1개, 등급 제한 있음). 쓰기는 Functions 전용(`personal_member_taxonomy.ts`), Rules는 클라이언트 쓰기 deny. **회원 분류용 내부 라벨이라 커뮤니티 그룹과 다른 개념** |
| 프로필 수정 권한 | `trainer_profiles/{uid}` update는 허용 키 목록(`displayName,nickname,phone,profileImageUrl,locale,timezone,contractProfileDraft,updatedAt`)만 가능. 새 프로필 필드를 쓰려면 Rules 변경(승인) |
| 마이페이지 소속 | `my_page.dart`에 `affiliationType`, `centerLocation`, `centerLogoPath`. **센터 이름 필드는 마이페이지에서 확인 못 함**(계약서 설정에는 `centerName`). 저장 경로는 작업자가 확인 |
| 회원 초대·연결 | 저장소에 **구현 없음**(`member_links`, `issueMemberInviteV1` 등은 제안서에만 있음) |
| 레슨일지 영상 | `step3_video_memo.dart`가 "준비 중" 자리표시 |
| 레슨일지 회원 카드 보내기 | 사장님 설명으로 존재한다고 알고 있으나 **코드 위치·저장 방식 미확인** |
| 회원 Rules | `members`, `training_logs` 등 회원 직접 read/write는 deny 유지 |

## 2. 단계별 작업

### 단계 A. 소속센터 입력 정리 (작은 변경, 승인: Rules 가능성)
- 마이페이지 센터 영역에 **센터 이름** 입력 확인/추가. 이미 `centerName`이 어디 저장되는지 먼저 파악하고 중복 저장 금지.
- "회원앱에 센터 표시" 스위치(기본 꺼짐). 센터 이름은 자유 입력이라 표기 흔들림이 있으므로 **그룹 키로 직접 쓰지 않는다**(단계 B에서 그룹에 연결).
- 저장 필드가 `trainer_profiles` 허용 키 밖이면 Rules 변경이 필요하므로 **멈추고 승인 요청**.
- 완료 기준: 기존 저장 값 유지, 신규 필드는 선택값, 구버전 앱에 영향 없음.

### 단계 B. 커뮤니티 그룹 관리 (신규 기능, 승인: 새 컬렉션·Rules·Functions)
- 강사가 그룹을 **만들기·이름 수정·보관(삭제 대신)** 한다. 이름 자유(예: 강남, 관악, 모어댄짐). 개수 기본 한도는 정하고 조정 가능(초기 제안 10개).
- 그룹은 두 종류: **센터 그룹**(마이페이지 센터와 연결)과 **강사 그룹**(연결 없음). 센터 미연동 강사는 강사 그룹만 쓴다.
- 이름은 회원앱에 그대로 보이므로 입력 시 안내("회원에게 보이는 이름이에요"), 길이 제한, 금지 단어는 운영 정책(후속).
- UI 이름: **"커뮤니티 그룹"**. 기존 "회원 분류 그룹"(personal_groups)과 **다른 화면·다른 용어**로 둔다. 기존 분류 그룹을 재사용하지 않는다(내부 라벨 노출 위험, 회원당 1개 제약).
- 화면 위치 제안: 더보기 또는 회원관리 안 "커뮤니티 그룹" 메뉴(작업자가 현재 구조에 맞게 제안, 승인).
- 서버: 생성·수정·보관은 Callable(클라이언트 직접 쓰기 deny). 초안 컬렉션 이름 `community_groups` — 확정은 승인 시.

### 단계 C. 회원 초대 링크 발급 (승인: Functions·Rules, 로그인 방식 확정 선행)
- 진입점: 회원 카드, 회원 목록. "회원앱에 초대" → **그룹 선택(복수 가능, 필수 아님)** → 링크 생성 → 공유 시트로 전달.
- 상태: 대기 / 수락됨 / 만료 / 취소. 재발급·취소 가능. 링크는 만료 시간과 1회 사용 제한을 서버가 보장.
- 개인정보: 링크에 이름·연락처를 넣지 않는다(토큰만). 초대 대상 회원 식별은 서버가 한다.
- 서버 API는 제안서의 `issueMemberInviteV1` / `claimMemberInviteV1` 구조를 따르되 **그룹 ID 목록**을 포함하도록 확장. 제안서와 달라지는 부분은 `DECISIONS.md`에 기록.
- 공유 수단이 현재 앱에 있는지 확인하고, 없으면 새 의존성 **승인 요청**(OS 기본 공유 시트 사용 가능 여부 먼저 검토).
- 선행: 회원앱 로그인 방식 확정, 1.0.7 배포 후.

### 단계 D. 연결된 회원 표시·관리 (승인: 회원 데이터 구조)
- 회원 카드에 연결 상태 배지(미연결/초대중/연결됨)와 소속 그룹 표시. 연결 해제 버튼(확인 대화상자, 해제하면 회원앱의 일정 공유가 즉시 끊김).
- 회원이 그룹을 바꾸거나 자기기재 소속을 적는 것은 강사 앱 표시에 영향 주지 않는다(자기기재는 미인증 그룹이므로 강사 앱에 노출하지 않는다).
- 기존 `members` 문서 필드는 **변경하지 않고**, 연결 정보는 별도 컬렉션(`member_links` 초안)에 둔다.

### 단계 E. 그룹 게시판 읽기 전용 (후속, 회원앱 커뮤니티 이후)
- "내 그룹 게시판": 강사 자기 그룹의 게시글 목록 읽기. **글쓰기·댓글 없음**.
- 신고된 글 알림은 운영자(사장님) 도구에서 처리하고 강사 앱에는 넣지 않는다.
- 회원앱 커뮤니티 정책이 확정되고 법적 확인이 끝나기 전에는 만들지 않는다.

### 단계 F. 일정 공유·알림·사인 (기존 제안서 범위)
- **일정 공유**: 연결된 회원에게 그 회원의 레슨 일정을 보여 준다. 공유 범위(일정 전체 vs 레슨명·시간만)와 강사별 켜기/끄기는 사장님 결정.
- **레슨 알림**: 레슨 전 알림 시간(기존 알림 설정과 정합) — 서버 푸시 설계는 승인.
- **레슨 사인**: 제안서의 `inspectMemberAttendanceV1`/`submitMemberAttendanceV1`을 따른다. 1.0.7 이후.
- **채팅**: 가장 마지막. 연결·로그인 확정 후 설계(`member-app-feature-direction.md` 4장).

### 단계 G. 레슨일지 영상 단계 (후속, 저장 방식 결정 선행)
- `Step3VideoMemo`("준비 중")를 구현. **링크 저장으로 먼저**(저장소 비용 없음), 업로드는 요금제 결정 후.
- 영상은 부위·운동명에 묶고, 연결 회원에게 노출 여부를 영상 단위로 선택.
- 영상 재생 패키지는 범주 승인됨. **구체 패키지는 추가 직전에 목록 보고.**

## 3. 데이터·서버 초안 (확정 아님, 승인 시 구체화)
- 새 컬렉션 후보: `community_groups`, 그룹 소속 멤버십, `member_links`, 초대 토큰. 모두 **클라이언트 직접 쓰기 deny**, 쓰기는 Callable.
- 강사는 자기 그룹·자기 연결만 읽는다. 회원은 자기 소속 그룹과 연결만 읽는다. 다른 강사·회원 접근은 deny.
- 기존 필드·컬렉션 삭제·이름 변경 없음. 과거 데이터 호환 유지(신규 필드는 선택값).
- `workspaceType`(personal/legacy) 구분: 초대 대상이 개인 워크스페이스 회원만인지 작업자가 확인하고 `DECISIONS.md`에 기록.

## 4. 공통 규칙
- 디자인은 현재 강사 앱 테마(`AppColors`, 라이트·다크·룰루랄라 3종)를 그대로 쓴다. 새 색·새 컴포넌트 규칙을 만들지 않는다.
- 새 의존성은 추가 전에 중단하고 승인받는다. `home_page.dart` 분리 파일은 `home_` 접두어.
- 한국어 용어: 레슨, 회원, 레슨일지, 회원관리, 운영통계. 새 용어 "커뮤니티 그룹"·"초대"는 이 문서 기준.
- 변경 파일만 `dart format`. 순서: `flutter analyze` → 관련 단위 테스트 → `flutter test` → `flutter build apk --debug`. Rules·Functions는 Emulator 테스트(`firebase-emulator-tests`)로 검증하고 **배포는 별도 승인**.
- 같은 원인으로 3회 실패하면 중단 보고. 완료 후 `RUN_LOG.md`, `BACKLOG.md` 갱신.

## 5. 수용 기준 (단계별 공통)
- [ ] 요청한 단계만 변경되었고 기존 화면·데이터가 그대로다.
- [ ] 새 필드는 선택값이며 구버전 앱·기존 회원 데이터가 깨지지 않는다.
- [ ] 클라이언트에서 새 컬렉션을 직접 쓸 수 없다(Emulator 테스트로 증명).
- [ ] 다른 강사의 그룹·연결·초대를 읽거나 바꿀 수 없다(Emulator 테스트).
- [ ] 초대 링크에 개인정보가 없고, 만료·1회 사용·취소가 서버에서 동작한다.
- [ ] analyze/test/build 결과가 기준보다 나빠지지 않았다. 검증하지 못한 항목은 보고서에 명시했다.
