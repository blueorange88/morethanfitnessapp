# 회원앱 기능 방향 — 채팅 · GPS 러닝 · SVG 개인 운동일지 · 강사 영상

작성: 2026-11-11. 상태: **방향 제안(초안).** 구현 아님. 서버·Rules·요금제·개인정보·새 의존성이 걸린 항목은 모두 AGENTS.md상 **구현 전 별도 승인**이 필요하다.
전제: 디자인은 `member-app-work-order.md`를 따른다. 회원앱 코드는 이 저장소에 없으므로 아래는 설계 방향이고, 회원앱 코드 구조는 팀이 확인한다.

## 0. 확인된 현재 상태 (이 저장소 기준)
- 강사 앱 레슨일지의 영상·음성 단계는 **"준비 중" 자리표시**이며 저장하지 않는다(`step3_video_memo.dart`).
- 강사 앱에는 영상 재생 패키지와 위치(GPS) 권한이 **없다**(pubspec·AndroidManifest 확인).
- 회원 연동 제안서에 SVG 4종(남/녀 앞/뒤) 참조 파일이 있고, 부위 ID에 자동 생성·중복 값이 있어 **안정 ID 매핑표가 먼저** 필요하다.
- 회원은 `members`·`training_logs` 등을 직접 읽고 쓸 수 없다(Rules deny 유지). 채팅·영상은 **회원–강사 연결(`member_links`)** 이 선행 조건이다.

## 1. 추천 순서
| 순서 | 기능 | 이유 |
|---|---|---|
| 1 | 디자인 통일(진행 중) | 이후 기능이 같은 토큰 위에 올라감 |
| 2 | **SVG 개인 운동일지** | 회원 혼자 쓰는 기능이라 강사 연결 없이 시작 가능. 앱 사용 습관(재방문)의 핵심 |
| 3 | **GPS 러닝 기록** | 이것도 회원 단독. 로컬 저장부터 시작하면 서버 부담이 작음 |
| 4 | **채팅** | 회원–강사 연결 API·로그인 방식 확정 후. 사인·계약 카드와 함께 |
| 5 | **강사 영상** | 저장소·요금제 결정과 강사 앱 쪽 업로드 기능이 모두 필요해 가장 무거움 |

2·3은 회원 본인 데이터라 새 회원 전용 컬렉션이 필요한 정도(Rules 승인)이고, 4·5는 두 앱과 서버가 함께 움직인다.

## 2. SVG 개인 운동일지
**목표**: 회원이 몸 그림에서 부위를 눌러 오늘 한 운동을 5초 안에 기록한다. 강사 레슨일지(강사용 정식 기록)와 **별개의 회원 개인 기록**이다.

- 흐름: 부위 선택 → 운동 선택(최근·자주 쓴 순) → 세트·반복·무게·시간 → 저장. 한 번에 여러 부위, 마지막 입력 복사("직전과 같게").
- 선택 색: 골드 계열(지시서 1.5 바디맵 색). 최근 7일 기록이 있는 부위는 진한 골드 점, 오래 안 쓴 부위는 옅게(균형 보기).
- **SVG 부위 ID 매핑표 먼저**: `bodyGender/bodyView/bodySide + 안정 bodyPartId` 표를 만들고 SVG의 자동 생성 ID는 직접 쓰지 않는다. 이 표는 강사 앱 레슨일지의 부위와도 맞춰 두어야 나중에 같은 부위로 비교·공유된다.
- 데이터: 회원 본인만 읽고 쓰는 **새 컬렉션**(예: 회원 UID 하위). 기본은 **나만 보는 기록**이고, 원하면 "게시판에 올리기"로 **커뮤니티 게시판**(전체/소속 헬스장/소속 트레이너 게시판)에 카드로 올린다. 강사에게 개별 전송·확인받는 구조가 아니다(6장). 강사 `training_logs`와 섞지 않는다.
- 오프라인: 기기에 먼저 저장하고 온라인일 때 동기화(앞서 정한 오프라인 방향과 동일).
- 의존성: SVG 렌더링 패키지가 필요하면 **추가 전 승인**(기본 `CustomPaint`+경로 파싱으로 가능한지 먼저 검토).
- 승인 필요: 새 컬렉션과 Rules, 건강 정보 동의(재활·통증 기록은 민감 정보 소지).

## 3. GPS 러닝 기록
**목표**: 달리기·걷기를 앱에서 기록하고 홈 타일·운동 탭에서 본다.

- 1단계는 **기록 + 요약**: 거리, 시간, 평균 페이스, 구간 페이스, 경로선. 지도 타일 없이 **경로선만 직접 그린다**(지도 SDK·키·요금 부담 회피). 지도는 후속.
- 안드로이드 구현 포인트: 달리는 동안 화면이 꺼져도 기록되도록 **포그라운드 서비스(상단 알림 표시)** 를 쓰고, 시작은 사용자가 앱을 보고 있을 때만 하게 해 **백그라운드 위치 권한은 요청하지 않는다**(심사·동의 부담이 크게 줄어듦). 배터리 소모와 GPS 튐(정확도 필터, 최소 이동 거리)을 기준에 넣는다.
- 저장: 달리는 중에는 기기 로컬, 종료 시 요약만 서버(경로는 점 수를 줄여 압축 저장하거나 로컬만 — 팀 결정).
- 개인정보: 위치는 민감하다. 출발·도착 근처 200m는 공유·표시에서 가리는 옵션을 기본으로, 공유는 회원이 켠 경우만. 위치정보 수집·이용 동의와 처리방침 반영은 **법적 확인 필요**.
- 의존성: 위치·포그라운드 서비스 패키지가 새로 필요하다 → **추가 전 승인**. 강사 앱에는 위치 권한이 없으므로 이 기능은 **회원앱 전용**으로 둔다.
- 후속: 러닝 요약 카드를 커뮤니티 게시판에 올리기(경로선은 올릴 때 회원이 선택, 기본 숨김).

## 4. 채팅 연결
**전제**: 회원–강사 연결(`member_links`)과 회원 로그인 방식이 확정되고 1.0.7 이후 서버 API가 구현된 뒤. 지금은 **구현하지 않는다**.

- 1단계: 연결된 코치와의 **1:1 텍스트**. 사진은 사진 정책 확정 후.
- 2단계: **카드 메시지** — 사인 출석 요청, 계약서 서명 요청, 레슨일지 요약 카드(강사가 보낸 것)를 대화 중간 카드로. 이미 제안된 "채팅 요청 카드 연동"과 같은 방향.
- 구조 원칙: 대화방은 연결 하나당 하나. **클라이언트 직접 쓰기는 연결 확인을 서버(Functions)나 Rules가 보장**해야 한다(아무나 아무에게 못 보내게). 목록은 최근 N개만 구독해 읽기 비용을 제한.
- 알림: FCM 푸시, 방해 금지 시간. 개인 전화번호 노출 없이 대화.
- 안전: 신고·차단, 회원이 연결을 끊으면 대화 접근 종료(보관 기간은 정책 결정). 14~17세 회원 관련 별도 검토.
- 트레이너가 광고·홍보를 대화로 보내는 걸 막는 규칙(커뮤니티 정책과 동일 기준).
- 승인 필요: 새 컬렉션·Rules·Functions, 푸시 설정, 개인정보 보관 기간.

## 5. 강사가 올린 영상 확인
**목표**: 강사가 운동 영상(자세 교정, 과제)을 올리면 연결된 회원이 앱에서 부위·운동별로 본다. 강사 앱의 영상 단계(현재 "준비 중")가 완성되어야 한다.

- 구성: 영상은 **부위(SVG) + 운동명**에 묶어 회원 운동 탭에서 "내 코치 영상"으로 노출. 회원별 과제 영상(레슨 후 보내기)과 공용 영상으로 나눌 수 있다.
- 저장 방식 선택(결정 필요):
  - A. **외부 링크**(비공개/일부 공개 링크 등)만 저장: 비용·저장소 없음, 외부 서비스 의존·정책 변화 위험.
  - B. **앱에서 업로드**(압축 후 클라우드 저장): 통제는 좋지만 저장·전송 비용과 업로드 처리(압축·재시도)가 큼. 짧은 클립(예: 60초 이내, 720p 안팎)부터.
  - 제안: **A로 시작해 구조를 검증하고 B는 요금제 결정 후.**
- 권한: 영상은 **연결된 회원만** 읽는다(Rules). 연결 해제 시 접근 종료. 화면 녹화는 막을 수 없으므로 "강사 저작물 공유 금지" 문구와 강사 약관에 저작권·초상 동의를 넣는다.
- 회원 앱 화면: 영상 목록(부위 칩), 재생 화면, 시청 완료 표시("봤어요")는 강사에게 읽음으로 전달 가능.
- 의존성: 영상 재생 패키지가 새로 필요하다(양 앱) → **추가 전 승인**.
- 승인 필요: 저장소·요금제, Rules, 강사 약관·동의, 강사 앱 레슨일지 영상 단계 구현.

## 6. 공통 선행 결정 (사장님, 2026-11-11 답변 반영)
1. **연결 방식(확정 방향)**: 회원은 자유 가입, 강사가 **초대 링크**를 보내면 회원이 수락해 연결된다. 연결되면 레슨 알림·일정 공유·레슨 사인 확인·채팅이 열린다. 이미 제안된 `issueMemberInviteV1`(강사 발급) / `claimMemberInviteV1`(회원 수락) / `member_links` 구조와 같은 방향이다. 서버 구현은 1.0.7 출시 후 별도 승인.
2. **두 갈래 구조(사장님 정정 반영)**: ① **1:1 연결(초대 링크)** = 레슨 알림·일정·사인·채팅 전용. ② **커뮤니티 게시판** = 운동 기록·러닝은 코치에게 보내는 게 아니라 **게시판에 올리는 것**. 강사에게 하나하나 보내 확인받는 시스템이 아니다. 아래 "공유 등급"은 이 구조로 다시 썼다.
3. 사진·영상 저장소와 요금제: 사진 정책 틀(`community-photo-policy-draft.md`)과 **같은 결정**으로 처리(인지함).
4. 법적 확인: `legal-check-bundle.md`로 묶음 정리.
5. **새 패키지 승인(범주)**: SVG 렌더링, 위치·포그라운드 서비스, 영상 재생 — 범주는 승인됨. **구체 패키지 이름·버전은 추가 직전에 목록으로 보고**하고 사용한다(AGENTS.md).

### 공유 구조 (제안, 사장님 정정 반영)
**① 1:1 연결(초대 링크)에서 코치가 보는 것**: 레슨 일정·알림, 출석·레슨 사인, 채팅, 코치가 보낸 레슨일지 요약 카드. 회원의 운동일지·러닝은 **자동으로 코치에게 가지 않는다.**

**② 커뮤니티 게시판에 올리는 것**: 회원이 "게시판에 올리기"를 눌러야 올라간다. 올릴 때 게시판을 고른다.
| 게시판 | 누가 보나 | 단계 |
|---|---|---|
| 전체 | 모든 가입 회원 | 1 |
| 소속 헬스장 | 같은 헬스장 소속 회원(+ 소속 트레이너는 읽기만) | 2 |
| 소속 트레이너 | 같은 트레이너에 연결된 회원들(+ 그 트레이너는 읽기만) | 2 |
| (같은 지역) | 같은 시·구 회원 | 2 |
- 트레이너는 게시판을 **읽을 수만** 있고 글은 쓰지 못한다(이미 정한 정책 유지).
- 올리는 카드는 요약(운동·세트·시간, 러닝 거리·시간·페이스)이 기본이다. **러닝 경로, 통증·재활 메모, 체중·인바디·눈바디 사진은 올릴 때 회원이 직접 포함시킨 경우만** 들어간다(기본 제외).
- 올린 글은 지우거나 범위를 좁힐 수 있다. 신고·숨김·경고·정지 규칙은 커뮤니티 정책 그대로.
- **소속 확인 방법 → 아래 "그룹 모델"로 확정 방향(2026-11-11 사장님 답변)**.

### 그룹 모델 (자유도를 넓게, 차후 수정 전제)
**원칙**: 게시판의 단위는 헬스장·트레이너가 아니라 **그룹**이다. 그룹마다 게시판이 하나. 회원이 목록에서 헬스장·트레이너를 고르는 기능은 **만들지 않는다**(확정). 소속이 없는 일반 가입자의 트레이너 연결은 **차후 매칭 시스템**이 담당한다.

| 그룹 종류 | 만드는 사람 | 가입 방법 | 신뢰 표시 |
|---|---|---|---|
| ① 센터 그룹 | 강사 앱 마이페이지에 **소속센터를 기재·연동**한 강사 | 그 강사의 초대 링크 | 인증 |
| ② 강사 그룹 | 강사(센터 연동을 안 한 경우 포함). 예: 그룹1 "강남", 그룹2 "관악". 이름·개수는 강사 자유 | 강사가 초대할 때 **어느 그룹에 넣을지 선택** | 인증 |
| ③ 자기기재 그룹 | 회원 본인이 마이페이지에 소속을 **자유 입력**(예: 모어댄짐, 타지역) | 입력만으로 자동 합류 | **미인증** 표시 |

- 일반 가입자(소속 없음)는 마이페이지에서 ③을 적을 수 있고, 안 적으면 "전체" 게시판만 쓴다.
- ③은 같은 표기(공백·대소문자 정규화 후)를 쓴 회원끼리 자동으로 모인다. "모어댄짐" 그룹과 "타지역(기타)" 그룹처럼 **지역이 달라도 그룹이 생길 수 있다.** 지역·헬스장 이름이 달라 그룹이 흩어지는 문제는 운영하며 병합 도구로 정리한다(운영자).
- **인증 그룹 게시판은 초대 수락자만** 들어온다. 자기기재로는 들어올 수 없다(남의 헬스장 이름을 적어 그 게시판을 보는 것 방지). 자기기재 그룹은 같은 이름이어도 별도 게시판이다.
- 한 회원은 여러 그룹에 속할 수 있다(기본 최대 3개, 조정 가능). 올릴 때 그룹을 고른다.
- 트레이너는 **자기가 만든(또는 센터 연동한) 그룹 게시판을 읽기만** 한다. 글은 쓸 수 없다.
- 강사 앱 마이페이지의 현재 필드는 `affiliationType`, `centerLocation`, `centerLogoPath`다(코드 확인). 센터 **이름** 필드가 마이페이지에 따로 있는지는 미확인이고(계약서 설정에는 `centerName`이 있음), 센터 이름은 자유 입력이라 표기 흔들림으로 자동 매칭이 불안정하다. 그래서 센터를 곧바로 그룹 키로 쓰지 않고 **강사가 만든 그룹에 센터를 연결**하는 방식을 쓴다.
- **강사 앱 변경이 따른다**: 그룹 만들기·이름 수정, 초대 시 그룹 선택. 이는 디자인 통일(강사 앱 변경 없음)과 다른 **기능 작업이므로 별도 승인**이 필요하다. 서버(그룹·멤버십 컬렉션, Rules)도 별도 승인.
- 자기기재 입력의 해석(확인 요청): "그룹1 모어댄짐 / 그룹2 타지역"을 회원이 마이페이지에서 **자기 소속 칸을 적으면 그 표기로 그룹이 생기는 것**으로 이해했다. 다르게 의도하셨다면 알려 달라.
- 코치가 회원 운동을 보고 피드백하는 흐름이 필요하면 게시판 댓글이 아니라 **별도 기능(후속)** 으로 다룬다. 지금은 만들지 않는다.

## 7. 이 문서의 한계
- 회원앱 현재 구조·패키지를 보지 못해 구현 난이도는 팀 확인이 필요하다.
- 비용·시간 수치는 넣지 않았다(요금제·사용량 결정 후 산정).
